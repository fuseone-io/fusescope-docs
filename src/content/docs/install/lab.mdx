The charts repository ships a complete lab in
[`examples/lab`](https://github.com/fuseone-io/fusescope-charts/tree/main/examples/lab). It
is the FuseOne lab, so hostnames are under `fuseone.io`; change them to deploy it
elsewhere.

## Components

| Component | Release / namespace | URL |
|---|---|---|
| FuseScope (backend, UI, collector, ClickHouse, PostgreSQL) | `fusescope` / `fusescope-lab` | `https://fusescope.fuseone.io` |
| OTLP/HTTP ingestion | collector ingress | `https://otlp.fusescope.fuseone.io` |
| Keycloak (OIDC provider, realm `fusescope`) | manifest / `fusescope-lab` | `https://sso.fuseone.io` |
| k8s-infra (cluster metrics, events, logs) | `k8s-infra` / `fusescope-lab` | — |
| OpenTelemetry Demo | `otel-demo` / `otel-demo` | `https://otel-demo.fuseone.io` |

| File | Contents |
|---|---|
| `values-fusescope.yaml` | PostgreSQL metastore, ClickHouse sizing, ingresses, SSO in `signoz.config` |
| `values-k8s-infra.yaml` | Cluster name and the collector endpoint over OTLP/HTTP |
| `values-otel-demo.yaml` | OpenTelemetry Demo sending only to FuseScope |
| `keycloak.yaml`, `keycloak-realm.json.tmpl` | Keycloak and its realm, client, groups and users |
| `deploy.sh` | Installs everything |

## Requirements

- A cluster with an NGINX ingress class and a cert-manager `ClusterIssuer` named
  `letsencrypt-prod`.
- The `longhorn` storage class, or change `global.storageClass` in `values-fusescope.yaml`.
- DNS for the hostnames above pointing at the ingress.
- `kubectl`, `helm`, `openssl` and `envsubst` on the machine running the script.

## Deploy

<Steps>

1. Clone the charts repository:

   ```bash
   git clone https://github.com/fuseone-io/fusescope-charts
   cd fusescope-charts/examples/lab
   ```

2. Run the script against the cluster:

   ```bash
   KUBECONFIG=/path/to/kubeconfig ./deploy.sh
   ```

</Steps>

`deploy.sh` installs the charts from the local checkout and is idempotent. On the first
run it generates the OIDC client secret, the Keycloak admin password and the password of
the SSO users, keeps them in secrets of the `fusescope-lab` namespace and renders the
Keycloak realm from `keycloak-realm.json.tmpl`. No secret is stored in the repository.

`FUSESCOPE_LAB_NAMESPACE` (default `fusescope-lab`) and `FUSESCOPE_LAB_DEMO_NAMESPACE`
(default `otel-demo`) change the namespaces.

## Sign in

Create the first FuseScope admin on the sign-up page with an email outside
`lab.fuseone.io`. The SSO domain, declared in the configuration file, is applied to the
new organization within a minute and shows up read-only in
*Settings → Single Sign-on*.

Keycloak groups map to FuseScope roles:

| User | Keycloak group | FuseScope role |
|---|---|---|
| `admin@lab.fuseone.io` | `fusescope-admins` | Admin |
| `editor@lab.fuseone.io` | `fusescope-editors` | Editor |
| `viewer@lab.fuseone.io` | `fusescope-viewers` | Viewer (default role) |

The users share one generated password:

```bash
kubectl -n fusescope-lab get secret fusescope-lab-oidc-users \
  -o jsonpath='{.data.password}' | base64 -d
```

The Keycloak admin password is in the `admin-password` key of the
`fusescope-lab-keycloak` secret.

<Aside>
  See [Single sign-on](/fusescope-docs/configuration/sso/) for how the domain and role
  mapping are declared.
</Aside>

## Remove

```bash
helm -n otel-demo uninstall otel-demo
helm -n fusescope-lab uninstall k8s-infra fusescope
kubectl delete namespace otel-demo fusescope-lab
```
