**Use this page when** you run on Kubernetes and want pod logs, node and pod metrics and cluster
events in FuseScope, without changing your applications, or when an
[instrumentation check](/observe/infrastructure/#instrumentation-checks) on
the **Infrastructure** page says a metric or attribute is missing.

The `fusescope` chart's agents (`fusescopeAgent`, a DaemonSet) collect pod logs, node metrics
and kubelet stats on every node and send them over mTLS with TLS 1.3 and a token. Cluster object
metrics and Kubernetes events are [not supported yet](#not-supported-yet).

## Node telemetry with the FuseScope agents

The `fusescope` chart's agents collect each node's pod logs, host metrics and kubelet stats, add
the pod's Kubernetes attributes, and send them to the gateway over mTLS. They write nothing and
take no remote configuration.

```yaml
fusescopeCollector:
  agentListener:
    enabled: true
    tls:
      certManager: {enabled: true, issuerRef: {name: internal-ca}}
    token:
      existingSecret: fusescope-agent-token
fusescopeAgent:
  enabled: true
  tls:
    certManager: {enabled: true, issuerRef: {name: internal-ca}}
```

Each source has its own switch, all on by default: `fusescopeAgent.podLogs`,
`fusescopeAgent.hostMetrics` and `fusescopeAgent.kubeletStats`. With `podLogs` or `hostMetrics`
the agent runs as root, as nodes keep those files readable by root only; see
[Security](/collector/security/#agents) for its privileges and the Pod Security level it needs.
The [production setup](/collector/production-setup/) has the complete values.

What the agents do not collect yet:

- **cluster object metrics** (`k8s_cluster`), such as `k8s.pod.phase` and deployment replica
  counts;
- **Kubernetes events**;
- **host network and process metrics**: without the host network namespace, the agents read the
  node's traffic from kubelet stats (`k8s.node.network.*`) instead;
- **`k8s.cluster.name`**, which the Infrastructure page checks for.

## Not supported yet

These have no supported path to FuseScope today:

- **Cluster object metrics** (`k8s_cluster`), such as `k8s.pod.phase`, `k8s.container.restarts`
  and deployment replica counts;
- **Kubernetes events**;
- **`k8s.cluster.name`** on the agents' data.

The `k8s-infra` chart collects the first two, but it sends without the TLS and token the
FuseScope agents require, so it could reach FuseScope only through the gateway's plaintext
receiver. That receiver is a temporary exception for migrating from SigNoz, with an exit
criterion, not a path for new collection, so `k8s-infra` is not supported with this chart.
The Infrastructure page's checks for these metrics stay unmet until FuseScope offers a secure
path for them.

## What each component sends

The [Infrastructure](/observe/infrastructure/) page checks for the metrics and attributes below
and names the collector component that should produce each one. This section says which chart
runs it, which value turns it on, and what to check when a metric is missing.

### hostmetrics receiver

Runs in the FuseScope agent on every node and reads the node's CPU, memory, load and file
systems: `system.cpu.time`, `system.memory.usage`, `system.cpu.load_average.15m` and
`system.filesystem.usage`. It feeds the **Hosts** tab.

- Turned on by `fusescopeAgent.hostMetrics.enabled` (default `true`), every
  `fusescopeAgent.hostMetrics.collectionInterval` (30 s).
- It reads the node through the host root mounted read-only at `/hostfs`. If CPU and memory
  arrive but `system.filesystem.usage` doesn't, check that the agent pods can mount it.
- It does not scrape the network or processes: without the host network namespace it would
  read the pod's own. The node's traffic comes from kubelet stats (`k8s.node.network.*`).

#### Hosts outside Kubernetes

The chart's agents run only in the cluster, and the chart exposes no endpoint for collectors
outside it. Hosts outside Kubernetes are not covered yet.

### kubeletstats receiver

Runs in the FuseScope agent and asks its node's kubelet for container, pod, node and volume
usage: `container.cpu.usage`, `container.memory.working_set`, `k8s.pod.cpu.usage`,
`k8s.pod.memory.working_set`, `k8s.node.cpu.usage`, `k8s.node.memory.working_set`
and the `k8s.volume.*` metrics.

- Turned on by `fusescopeAgent.kubeletStats.enabled` (default `true`).
- It authenticates with the agent's service account (`nodes/stats`, which the chart grants) and
  verifies the kubelet's serving certificate. Where kubelets serve a self-signed one, set
  `fusescopeAgent.kubeletStats.insecureSkipVerify: true` or turn kubelet stats off.
- The optional request and limit metrics, such as `k8s.pod.cpu_request_utilization`, are not
  collected.

### k8scluster receiver

Would watch the Kubernetes API for the state of objects: `k8s.pod.phase`,
`k8s.container.restarts`, `k8s.container.ready`, `k8s.node.allocatable_cpu`,
`k8s.node.condition_ready`, and the desired, current and ready counts of deployments, daemon
sets, stateful sets and jobs. No supported component runs it yet; see
[Not supported yet](#not-supported-yet).

### resourcedetection processor

Adds attributes that describe where the data comes from.

The FuseScope agents set `host.name` and `k8s.node.name` to the node's name, and `os.type`. They
do not set `k8s.cluster.name`.

### k8sattributes processor

Adds the Kubernetes names to metrics, logs and traces: `k8s.pod.uid`, `k8s.pod.name`,
`k8s.namespace.name`, `k8s.node.name`, `k8s.container.name` and the owner
(`k8s.deployment.name`, `k8s.statefulset.name`, `k8s.daemonset.name`, `k8s.job.name`).

- The FuseScope agents run it on everything they send, including OTLP from pods, limited to the
  pods of their own node. It needs permission to read pods, namespaces, nodes and replica sets;
  the chart grants it.
- A pod's first records, sent before the agent's cache sees the pod, can arrive without these
  attributes.

### Kubernetes events

Events such as `Back-off restarting failed container` would appear on the **Events** tab of a
pod, node or other object on the Infrastructure page. No supported component collects them yet;
see [Not supported yet](#not-supported-yet).
