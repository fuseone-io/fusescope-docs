The FuseScope agents read the log files of every container on every node and send them to
FuseScope over mTLS. You don't change your applications: anything a container writes to stdout
or stderr arrives as a log, labelled with its pod, namespace, container and node.

**Use this page when** you want pod logs in FuseScope, or want to know what the agents do with
them.

## Turn it on

The FuseScope agents' pod logs are on by default (`fusescopeAgent.podLogs.enabled`). The agents
themselves need `fusescopeAgent.enabled` and the gateway's agents' listener; see
[Kubernetes](/sending-data/kubernetes/#node-telemetry-with-the-fusescope-agents).

## What the agents do

- **Every pod's logs.** Each agent reads `/var/log/pods/*/*/*.log` on its node, mounted
  read-only. It leaves out the agents' own logs.
- **The container runtime's format.** The `container` operator parses the CRI-O, containerd or
  Docker line format and sets the stream and the time of each line.
- **Kubernetes attributes.** Each record carries `k8s.namespace.name`, `k8s.pod.name`,
  `k8s.pod.uid` and `k8s.container.name` from the file's path, and the node's `host.name` and
  `k8s.node.name`.
- **From the end, then resume.** On its first start an agent reads new lines only. It keeps its
  read offsets on the node (`fusescopeAgent.statePath`, `/var/lib/fusescope-agent` by default),
  so after a restart it resumes where it stopped instead of skipping or repeating lines.

<Aside type="caution" title="Root on the node">
  Nodes keep pod log files readable by root only, so with `podLogs` the agent runs as uid 0,
  locked down otherwise. The chart's README
  ([Agents](https://github.com/fuseone-io/fusescope-charts/tree/main/charts/fusescope#agents))
  explains its privileges and the Pod Security level its namespace needs.
</Aside>

## What they do not do

- **No per-namespace or per-pod selection.** The agents read every pod's logs on the node.
- **No multiline joining.** A Java stack trace arrives as one record per line.
- **No `service.name` rules.** Records carry the Kubernetes attributes above, not a service
  name.

[Log pipelines](/sending-data/log-pipelines/) can parse and enrich the records the agents send.

## Check that logs arrive

1. Open the [Logs explorer](/explore/logs/) and filter by `k8s.namespace.name` and
   `k8s.pod.name`.
2. If nothing arrives, check the agent on that pod's node:
   `kubectl -n fusescope logs daemonset/fusescope-agent`. Errors reading `/var/log/pods` usually
   mean the agent is not running as root, or the namespace's Pod Security level forbids host
   path volumes.
