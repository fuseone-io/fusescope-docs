FuseScope has no agent of its own: applications use the standard
[OpenTelemetry SDKs](https://opentelemetry.io/docs/languages/) and export OTLP to the
FuseScope collector. Most languages offer zero-code instrumentation that covers common
frameworks, HTTP clients and database drivers without changing your code.

## Configure the exporter

Every SDK reads the same
[environment variables](https://opentelemetry.io/docs/languages/sdk-configuration/):

| Variable | Example | Purpose |
|---|---|---|
| `OTEL_SERVICE_NAME` | `checkout` | Service name shown in APM and traces. |
| `OTEL_RESOURCE_ATTRIBUTES` | `deployment.environment=production,service.version=1.4.2` | Extra resource attributes, comma separated. |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://fusescope-otel-collector.fusescope.svc.cluster.local:4318` | Collector endpoint. |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `http/protobuf` | `http/protobuf` on port 4318 or `grpc` on port 4317. |

See [OTLP](/fusescope-docs/sending-data/otlp/) for the collector endpoints and how to
reach them from outside the cluster.

<Aside>
  Set `deployment.environment` on every service: FuseScope uses it to filter services and
  traces by environment.
</Aside>

## Zero-code instrumentation

<Tabs>
  <TabItem label="Java">

Download `opentelemetry-javaagent.jar` from the
[Java agent releases](https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases)
and attach it to the JVM:

```bash
java -javaagent:/path/to/opentelemetry-javaagent.jar -jar app.jar
```

See [Java zero-code instrumentation](https://opentelemetry.io/docs/zero-code/java/agent/).

  </TabItem>
  <TabItem label="Python">

```bash
pip install opentelemetry-distro opentelemetry-exporter-otlp
opentelemetry-bootstrap -a install
opentelemetry-instrument python app.py
```

See [Python zero-code instrumentation](https://opentelemetry.io/docs/zero-code/python/).

  </TabItem>
  <TabItem label="Node.js">

```bash
npm install @opentelemetry/api @opentelemetry/auto-instrumentations-node
NODE_OPTIONS="--require @opentelemetry/auto-instrumentations-node/register" node app.js
```

See [JavaScript zero-code instrumentation](https://opentelemetry.io/docs/zero-code/js/).

  </TabItem>
  <TabItem label=".NET">

Install the OpenTelemetry .NET automatic instrumentation and run the application through
its launcher script. See
[.NET zero-code instrumentation](https://opentelemetry.io/docs/zero-code/dotnet/).

  </TabItem>
  <TabItem label="Go">

Go has no runtime agent. Initialise the SDK with an OTLP exporter in `main` and wrap
handlers and clients with the `otelhttp`, `otelgrpc` and similar instrumentation
libraries. See [Go getting started](https://opentelemetry.io/docs/languages/go/getting-started/).

  </TabItem>
</Tabs>

Other languages are listed in the
[OpenTelemetry language docs](https://opentelemetry.io/docs/languages/).

## On Kubernetes

Set the variables in the pod spec. `OTEL_RESOURCE_ATTRIBUTES` can carry pod metadata
through the downward API:

```yaml
env:
  - name: OTEL_SERVICE_NAME
    value: checkout
  - name: OTEL_EXPORTER_OTLP_ENDPOINT
    value: http://fusescope-otel-collector.fusescope.svc.cluster.local:4318
  - name: K8S_POD_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
  - name: OTEL_RESOURCE_ATTRIBUTES
    value: deployment.environment=production,k8s.pod.name=$(K8S_POD_NAME)
```

The [k8s-infra chart](/fusescope-docs/sending-data/kubernetes/) collects pod logs and
cluster metrics separately.

## Logs

Several SDKs can export application logs over OTLP with the trace and span IDs attached;
whether it is on by default depends on the language. Logs written to stdout or files can be
collected by a collector, such as the k8s-infra agent, and parsed with
[log pipelines](/fusescope-docs/sending-data/log-pipelines/).
