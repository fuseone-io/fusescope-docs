PHP [auto-instrumentation](https://opentelemetry.io/docs/zero-code/php/) has two parts: the
`opentelemetry` PHP extension, which hooks into function calls, and Composer packages that
use those hooks for Laravel, Symfony, Slim, PDO, Guzzle, PSR-18 clients and
[more](https://github.com/open-telemetry/opentelemetry-php-contrib/tree/main/src/Instrumentation).
You don't change your code.

**Use this page when** you run a PHP application (Laravel, Symfony, WordPress or plain PHP)
and want it in FuseScope.

| Signal | Status | What is sent |
|---|---|---|
| Traces | Stable | Spans for requests, HTTP calls, database queries. |
| Metrics | Stable | What your code records through the API. |
| Logs | Stable | PSR-3 logger records (Monolog, Laravel) with trace IDs. |

## Prerequisites

- PHP 8.1 or later (the extension supports 8.0, current SDK packages need 8.1).
- Composer, with your app using its autoloader (`vendor/autoload.php`).
- To build the extension from source: `gcc`, `make` and `autoconf`.
- A FuseScope collector you can reach on port 4317 or 4318. See [OTLP](/sending-data/otlp/).

## Install

<Steps>

1. Install the extension, with one of:

   ```bash
   pecl install opentelemetry
   # or, with PIE
   pie install open-telemetry/ext-opentelemetry
   # or, in Docker images with docker-php-extension-installer
   install-php-extensions opentelemetry
   ```

2. Enable it in `php.ini` (PIE and `install-php-extensions` do this for you):

   ```ini title="php.ini"
   [opentelemetry]
   extension=opentelemetry
   ```

   Check it loads with `php --ri opentelemetry`.

3. Add the SDK, the OTLP exporter, an HTTP client for the exporter, and the instrumentation
   for your framework and libraries:

   ```bash
   composer require \
     open-telemetry/sdk \
     open-telemetry/exporter-otlp \
     php-http/guzzle7-adapter \
     open-telemetry/opentelemetry-auto-laravel \
     open-telemetry/opentelemetry-auto-pdo \
     open-telemetry/opentelemetry-auto-guzzle
   ```

   Swap `auto-laravel` for `auto-symfony`, `auto-slim`, `auto-wordpress` and so on. Each
   package is listed in the
   [OpenTelemetry registry](https://opentelemetry.io/ecosystem/registry/?language=php&component=instrumentation).

</Steps>

## Configure and run

```bash
export OTEL_PHP_AUTOLOAD_ENABLED=true
export OTEL_SERVICE_NAME=checkout
export OTEL_RESOURCE_ATTRIBUTES=deployment.environment.name=production,service.version=1.4.2
export OTEL_TRACES_EXPORTER=otlp
export OTEL_METRICS_EXPORTER=otlp
export OTEL_LOGS_EXPORTER=otlp
# The exporter variables of "Send to FuseScope" below: they work only in a pod
# of the Kubernetes cluster that runs FuseScope.
export OTEL_PROPAGATORS=baggage,tracecontext
php -S localhost:8080 -t public
```

`OTEL_PHP_AUTOLOAD_ENABLED=true` makes the SDK start itself from `vendor/autoload.php`.
Without it, nothing is sent.

<Aside type="caution" title="PHP-FPM drops environment variables">
  By default PHP-FPM clears the environment before running scripts, so `OTEL_*` variables set
  on the container or service never reach PHP. Set `clear_env = no` in the pool config, add
  `env[OTEL_SERVICE_NAME] = checkout` lines to it, or put the settings in `php.ini`
  (`OTEL_SERVICE_NAME=checkout`, no `export`).
</Aside>

Another option on Linux is the
[PHP distro](https://opentelemetry.io/docs/zero-code/php/distro/): deb, rpm and apk
packages with production defaults, installed without Composer.

## Send to FuseScope

Inside the Kubernetes cluster that runs FuseScope, send to the FuseScope agent on the pod's
node. It accepts OTLP only over TLS 1.3 with a bearer token, and the chart turns it on with
`fusescopeAgent.otlp.enabled`; see [OTLP](/sending-data/otlp/) for the setup and the
credentials to copy into your namespace.

```bash
OTEL_EXPORTER_OTLP_ENDPOINT=https://fusescope-agent-otlp.fusescope.svc:4318
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
OTEL_EXPORTER_OTLP_CERTIFICATE=/etc/fusescope-agent-ca/ca.crt
OTEL_EXPORTER_OTLP_HEADERS=Authorization=Bearer%20<token>
```

For gRPC, use port 4317 and `OTEL_EXPORTER_OTLP_PROTOCOL=grpc`. Set the protocol explicitly:
defaults differ between SDKs and versions.

`%20` is the space after `Bearer`: the headers variable follows the W3C baggage syntax. The
[Kubernetes](#kubernetes) section below mounts the CA and reads the token from a Secret.

<Aside type="caution" title="Not from outside the cluster yet">
  The FuseScope chart exposes no OTLP endpoint outside the Kubernetes cluster that runs
  FuseScope. Applications on a VM, in Docker outside Kubernetes, or in another cluster have no
  supported path to send to FuseScope yet.
</Aside>

## Docker

This example installs the extension with `install-php-extensions` from
[mlocati/docker-php-extension-installer](https://github.com/mlocati/docker-php-extension-installer),
which also enables it:

```dockerfile title="Dockerfile"
FROM php:8.3-apache
COPY --from=mlocati/php-extension-installer /usr/bin/install-php-extensions /usr/local/bin/
RUN install-php-extensions opentelemetry zip
COPY --from=composer:2 /usr/bin/composer /usr/bin/composer
WORKDIR /var/www/html
COPY composer.json composer.lock ./
RUN composer install --no-dev --no-scripts --no-autoloader
COPY . .
RUN composer dump-autoload --optimize
```

Run the image in the cluster that runs FuseScope, with the variables of the
[Kubernetes](#kubernetes) section. Outside that cluster there is no supported
destination yet.

With a `php:*-fpm` image, apply the PHP-FPM caution above.

## Kubernetes

Set the variables in the pod spec. The downward API adds the pod name and namespace:

```yaml title="deployment.yaml"
env:
  - name: OTEL_PHP_AUTOLOAD_ENABLED
    value: "true"
  - name: OTEL_SERVICE_NAME
    value: checkout
  - name: OTEL_EXPORTER_OTLP_ENDPOINT
    value: https://fusescope-agent-otlp.fusescope.svc:4318
  - name: OTEL_EXPORTER_OTLP_PROTOCOL
    value: http/protobuf
  - name: OTEL_EXPORTER_OTLP_CERTIFICATE
    value: /etc/fusescope-agent-ca/ca.crt
  - name: FUSESCOPE_AGENT_TOKEN
    valueFrom:
      secretKeyRef: {name: fusescope-agent-otlp-token, key: token}
  - name: OTEL_EXPORTER_OTLP_HEADERS
    value: Authorization=Bearer%20$(FUSESCOPE_AGENT_TOKEN)
  - name: K8S_POD_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
  - name: K8S_NAMESPACE_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.namespace
  - name: OTEL_RESOURCE_ATTRIBUTES
    value: deployment.environment.name=production,k8s.pod.name=$(K8S_POD_NAME),k8s.namespace.name=$(K8S_NAMESPACE_NAME)
```

Mount the CA bundle at `/etc/fusescope-agent-ca`, from a Secret holding the agents' `ca.crt`
in the application's namespace (a `volumes` entry with `secret: {secretName:
fusescope-agent-ca}` and a matching `volumeMounts` entry). Copy that Secret and the token
Secret into the namespace first: a pod cannot read Secrets from another namespace.

`$(VAR)` only expands variables defined earlier in the list, so keep
`OTEL_RESOURCE_ATTRIBUTES` last.

## Logs

Any PSR-3 logger, which includes Monolog and the Laravel and Symfony loggers, can be
captured by the PSR-3 instrumentation:

```bash
composer require open-telemetry/opentelemetry-auto-psr3
```

| `OTEL_PHP_PSR3_MODE` | Effect |
|---|---|
| `inject` | Adds `trace_id` and `span_id` to each record's context, for your own log output. |
| `export` | Also exports each record over OTLP (needs `OTEL_LOGS_EXPORTER=otlp`). |

The PSR-3 package is still `0.x`. To attach OpenTelemetry to Monolog yourself instead, add
the handler from `open-telemetry/opentelemetry-logger-monolog`. If a collector already reads
your log files or stdout, use `inject` so each line is stored once.

## Check that data arrives

1. Send a few requests to the application.
2. Open [Services](/apm/services/). The service appears under its
   `OTEL_SERVICE_NAME` within a minute.
3. Open the [Traces explorer](/explore/traces/) and filter by
   `service.name`.

Nothing arrives? Check that the extension is loaded where requests run (`phpinfo()` lists
`opentelemetry`; the CLI and PHP-FPM can use different `php.ini` files), that
`OTEL_PHP_AUTOLOAD_ENABLED=true` reaches PHP (print `getenv('OTEL_PHP_AUTOLOAD_ENABLED')`),
and that an HTTP client such as `php-http/guzzle7-adapter` is installed.
