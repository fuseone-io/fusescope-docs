Ruby uses the [OpenTelemetry Ruby SDK](https://opentelemetry.io/docs/languages/ruby/) plus
`opentelemetry-instrumentation-all`, which instruments Rails, Rack, Sinatra, ActiveRecord,
`Net::HTTP`, Faraday, Redis, Sidekiq and
[more](https://github.com/open-telemetry/opentelemetry-ruby-contrib/tree/main/instrumentation).
You add a few lines of setup; the rest needs no code changes.

**Use this page when** you run a Ruby or Rails service and want it in FuseScope.

| Signal | Status | What is sent |
|---|---|---|
| Traces | Stable | Spans for requests, HTTP calls, database and jobs. |
| Metrics | Development | Your own metrics, through separate pre-1.0 gems. |
| Logs | Development | Ruby `Logger` and Rails logger records with trace IDs, through separate pre-1.0 gems. |

Metrics and logs work, but their gems are still `0.x` and can change between releases.
Traces alone need only the first three gems below.

## Prerequisites

- CRuby 3.3 or later (current gems require it). JRuby and TruffleRuby are best effort.
- Bundler.
- A FuseScope collector you can reach on port 4318. See [OTLP](/sending-data/otlp/).

<Aside type="caution" title="HTTP only">
  The Ruby SDK exports OTLP over HTTP (`http/protobuf`) only. Use port 4318; gRPC on 4317 is
  not supported, and spans are dropped with a warning if you set
  `OTEL_EXPORTER_OTLP_PROTOCOL=grpc`.
</Aside>

## Install

```bash
bundle add opentelemetry-sdk opentelemetry-exporter-otlp opentelemetry-instrumentation-all
# Optional: metrics and logs
bundle add opentelemetry-metrics-sdk opentelemetry-exporter-otlp-metrics
bundle add opentelemetry-logs-sdk opentelemetry-exporter-otlp-logs opentelemetry-instrumentation-logger
```

## Set up the SDK

<Steps>

1. Configure the SDK as early as possible. In Rails, use an initializer:

   ```ruby title="config/initializers/opentelemetry.rb"
   require "opentelemetry/sdk"
   require "opentelemetry/exporter/otlp"
   require "opentelemetry/instrumentation/all"

   # Optional: metrics and logs. Load them before configure.
   require "opentelemetry-metrics-sdk"
   require "opentelemetry/exporter/otlp_metrics"
   require "opentelemetry-logs-sdk"
   require "opentelemetry/exporter/otlp_logs"
   require "opentelemetry/instrumentation/logger"

   OpenTelemetry::SDK.configure do |c|
     c.use_all
   end
   ```

   `use_all` turns on every instrumentation whose library is loaded. Outside Rails, put this
   at the top of your entry point (for example `config.ru`), before the app is built.

2. Configure the exporter:

   ```bash
   export OTEL_SERVICE_NAME=checkout
   export OTEL_RESOURCE_ATTRIBUTES=deployment.environment.name=production,service.version=1.4.2
   export OTEL_EXPORTER_OTLP_ENDPOINT=https://fusescope-agent-otlp.fusescope.svc:4318
   export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
   export OTEL_EXPORTER_OTLP_CERTIFICATE=/etc/fusescope-agent-ca/ca.crt
   export FUSESCOPE_AGENT_TOKEN=<the token from the fusescope-agent-otlp-token Secret>
   export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer%20${FUSESCOPE_AGENT_TOKEN}"
   ```

   Traces, metrics and logs default to `otlp` once their gems are loaded. Set
   `OTEL_METRICS_EXPORTER=none` or `OTEL_LOGS_EXPORTER=none` to turn one off.

3. Run the app as usual:

   ```bash
   bundle exec rails server
   ```

</Steps>

## Send to FuseScope

Inside the Kubernetes cluster that runs FuseScope, send to the FuseScope agent on the pod's
node. It accepts OTLP only over TLS 1.3 with a bearer token, and the chart turns it on with
`fusescopeAgent.otlp.enabled`; see [OTLP](/sending-data/otlp/) for the setup and the
credentials to copy into your namespace.

```bash
OTEL_EXPORTER_OTLP_ENDPOINT=https://fusescope-agent-otlp.fusescope.svc:4318
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
OTEL_EXPORTER_OTLP_CERTIFICATE=/etc/fusescope-agent-ca/ca.crt
OTEL_EXPORTER_OTLP_HEADERS=Authorization=Bearer%20<token>
```

For gRPC, use port 4317 and `OTEL_EXPORTER_OTLP_PROTOCOL=grpc`. Set the protocol explicitly:
defaults differ between SDKs and versions.

`%20` is the space after `Bearer`: the headers variable follows the W3C baggage syntax. The
[Kubernetes](#kubernetes) section below mounts the CA and reads the token from a Secret.

<Aside type="caution" title="Not from outside the cluster yet">
  The FuseScope chart exposes no OTLP endpoint outside the Kubernetes cluster that runs
  FuseScope. Applications on a VM, in Docker outside Kubernetes, or in another cluster have no
  supported path to send to FuseScope yet.
</Aside>

## Docker

The gems are in the `Gemfile`, so `bundle install` adds them:

```dockerfile title="Dockerfile"
FROM ruby:3.3-slim
RUN apt-get update && apt-get install -y --no-install-recommends build-essential \
 && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY Gemfile Gemfile.lock ./
RUN bundle install
COPY . .
CMD ["bundle", "exec", "rails", "server", "-b", "0.0.0.0"]
```

Run the image in the cluster that runs FuseScope, with the variables of the
[Kubernetes](#kubernetes) section. Outside that cluster there is no supported
destination yet.

## Kubernetes

Set the variables in the pod spec. The downward API adds the pod name and namespace:

```yaml title="deployment.yaml"
env:
  - name: OTEL_SERVICE_NAME
    value: checkout
  - name: OTEL_EXPORTER_OTLP_ENDPOINT
    value: https://fusescope-agent-otlp.fusescope.svc:4318
  - name: OTEL_EXPORTER_OTLP_PROTOCOL
    value: http/protobuf
  - name: OTEL_EXPORTER_OTLP_CERTIFICATE
    value: /etc/fusescope-agent-ca/ca.crt
  - name: FUSESCOPE_AGENT_TOKEN
    valueFrom:
      secretKeyRef: {name: fusescope-agent-otlp-token, key: token}
  - name: OTEL_EXPORTER_OTLP_HEADERS
    value: Authorization=Bearer%20$(FUSESCOPE_AGENT_TOKEN)
  - name: K8S_POD_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
  - name: K8S_NAMESPACE_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.namespace
  - name: OTEL_RESOURCE_ATTRIBUTES
    value: deployment.environment.name=production,k8s.pod.name=$(K8S_POD_NAME),k8s.namespace.name=$(K8S_NAMESPACE_NAME)
```

Mount the CA bundle at `/etc/fusescope-agent-ca`, from a Secret holding the agents' `ca.crt`
in the application's namespace (a `volumes` entry with `secret: {secretName:
fusescope-agent-ca}` and a matching `volumeMounts` entry). Copy that Secret and the token
Secret into the namespace first: a pod cannot read Secrets from another namespace.

`$(VAR)` only expands variables defined earlier in the list, so keep
`OTEL_RESOURCE_ATTRIBUTES` last.

## Logs

With `opentelemetry-logs-sdk`, `opentelemetry-exporter-otlp-logs` and
`opentelemetry-instrumentation-logger` installed, `use_all` patches Ruby's `Logger` and the
Rails logger. Each record is still written where it was before, and is also exported over
OTLP with the trace and span IDs of the active span.

Logs support is in development: the gems are `0.x`. If a collector already reads your
stdout, set `OTEL_LOGS_EXPORTER=none` so each line is stored once.

## Check that data arrives

1. Send a few requests to the service.
2. Open [Services](/apm/services/). The service appears under its
   `OTEL_SERVICE_NAME` within a minute.
3. Open the [Traces explorer](/explore/traces/) and filter by
   `service.name`.

Nothing arrives? Run with `OTEL_TRACES_EXPORTER=console` to print spans to stdout, and look
for warnings from OpenTelemetry at boot, such as a missing exporter gem or an unsupported
protocol.
