Open **Logs** in the sidebar (`/logs/logs-explorer`). The page has three tabs:
**Explorer**, **Pipelines** ([Log pipelines](/fusescope-docs/sending-data/log-pipelines/)) and **Views**.

## Search logs

Write a filter in the search box with the
[search syntax](/fusescope-docs/querying/search-syntax/), pick a time range and click
**Run Query**. A quoted string on its own searches the log body:

```text
"connection refused" AND service.name = 'checkout'
```

The filter panel on the left lists quick filters. By default: Severity Text, Deployment
Environment, Service Name, Host Name, K8s Cluster Name, K8s Deployment Name, K8s Namespace
Name and K8s Pod Name. **Settings** adds or removes filters for everyone in the
organization; **Reset All** clears them. An attribute only appears as a quick filter once
logs carry it as an attribute, not just inside the body; a
[log pipeline](/fusescope-docs/sending-data/log-pipelines/) can parse it out.

## Views

| View | Shows |
|---|---|
| **List View** | The matching logs, newest first |
| **Time Series** | The query's aggregation as a chart, such as `count()` grouped by `severity_text` |
| **Table** | The query's aggregation as a table, one row per group |

Aggregation and group by are described in
[Query builder](/fusescope-docs/querying/query-builder/).

### List View options

- **Frequency chart** shows the log count over time above the list.
- **Order by** sorts by timestamp or another field.
- The format menu picks how each log is shown:

  | Format | Shows |
  |---|---|
  | **Raw** (default) | The body as one line, up to the max lines per row (1 to 10) |
  | **Default** | The timestamp and body, with the selected fields below |
  | **Column** | A table; **Edit columns** adds attributes as columns. `timestamp` and `body` are always shown |

  **Font Size** sets small, medium or large text.
- **Download** exports `csv` or `jsonl`, up to 10k, 30k or 50k rows, with all columns or
  the selected ones.

Hover over a log for **Show in Context** and **Copy Link**.

## Live tail

<Steps>

1. Switch to **List View**.
2. Open the time picker and choose **Live**.
3. Logs matching the filter stream in; the list keeps the latest 1000.

</Steps>

**Pause** and **Resume** stop and restart the stream. Changing the filter restarts it
with the new filter. Picking a time range, or switching view, leaves live mode.

## Log details

Click a log to open its details. Move to the previous or next log with the arrows or the
↑ and ↓ keys. The header shows the service, severity, namespace, environment, trace ID and
span ID; the trace ID opens the trace in a new tab. The actions menu has **Copy log** and
**Copy link to log**.

| Tab | Content |
|---|---|
| **Overview** | The body, attributes and resource attributes, as a list or JSON. Each value can be copied or used to **Filter for value**, **Filter out value**, **Group by field** or **Replace filters with this value**. |
| **Context** | The logs just before and after this one with the same resource attributes. **Load more** fetches 10 more in each direction, and a filter narrows the context. |
| **Metrics** | Host or Kubernetes metrics, when the log has host or Kubernetes attributes |

<Aside>
  The trace ID link works when the log carries `trace_id`. OpenTelemetry SDKs and log
  bridges add it when a log is written inside an active span. See
  [Instrument applications](/fusescope-docs/sending-data/instrumentation/#logs).
</Aside>

## Alerts, dashboards and saved views

As in the [Traces explorer](/fusescope-docs/explore/traces/#export-alert-add-to-dashboard),
**Create an alert** ([Alert rules](/fusescope-docs/alerts/alert-rules/)) and **Add to dashboard** reuse the current query, and the bar at the
bottom saves and loads views. The **Views** tab lists saved log views.
